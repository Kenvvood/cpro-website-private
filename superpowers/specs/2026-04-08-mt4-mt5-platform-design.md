# MT4/MT5 量化交易平台 - 设计方案

> **状态:** v1.1 更新
> **日期:** 2026-04-08
> **核心理念:** "前期开源整合工作是整个项目的地基和灵魂，竭尽全力获取所有源代码，检阅筛选出成色优秀的进行沉淀私有化"

## 一、正确的工作流程

```
┌─────────────────────────────────────────────────────────────────┐
│  Phase 1: 搜集阶段 (不做预判，竭尽所能)                              │
│  ───────────────────────────────────────────────────────────────  │
│  目标: 获取所有能找到的MT4/MT5开源源代码                              │
│  范围: GitHub + MQL5 Code Base + 指定网站群                        │
│  原则: 能找到源码的都找，不预先判断价值                                 │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 2: 筛选阶段                                              │
│  ───────────────────────────────────────────────────────────────  │
│  目标: 从海量资源中筛选出成色优秀的源代码                            │
│  标准: 代码质量 / 策略有效性 / 可维护性 / 许可协议                    │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 3: 沉淀阶段                                              │
│  ───────────────────────────────────────────────────────────────  │
│  目标: 沉淀优秀源代码仓库                                          │
│  输出: 分类整理 + 模块化拆分 + 接口标准化                           │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 4: 整合阶段                                              │
│  ───────────────────────────────────────────────────────────────  │
│  王牌EA: 挑选≤3个性价比最高的综合EA作为引流工具                       │
│  框架:   模块化整合，赋能自研开发                                    │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 5: 自研阶段                                              │
│  ───────────────────────────────────────────────────────────────  │
│  基于开源赋能的差异化自研产品                                        │
│  灵感库: 没有源代码的受欢迎产品 → 纳入自研计划                      │
└─────────────────────────────────────────────────────────────────┘
```

## 二、搜集范围（Phase 1）

### 2.1 目标数据源

| 数据源 | 类型 | URL | 说明 |
|--------|------|-----|------|
| **GitHub** | 代码平台 | github.com/topics/mql5 | 423+仓库，Star排序 |
| **MQL5 Code Base** | 官方市场 | mql5.com/zh/code/mt5 | 免费EA/指标库 |
| **mtctp.com** | 中文论坛 | mtctp.com | 源码下载 |
| **mql4ea.com** | 中文站 | mql4ea.com | 源码下载 |
| **fxznjy.com** | 交易站 | fxznjy.com/index.php | 源码下载 |
| **forex-station.com** | 英文论坛 | forex-station.com | 综合资源 |

### 2.2 搜集原则

| 原则 | 说明 |
|------|------|
| ✅ 有源代码免费下载 | 闭源/纯付费不在范围内 |
| ✅ 许可协议友好优先 | MIT > BSD > Apache > GPL |
| ⚠️ GPL协议 | 模块化隔离，避免传染 |
| ❌ 不判断价值 | 先全部搜集，筛选阶段再判断 |

### 2.3 搜集内容

| 类型 | 说明 |
|------|------|
| **EA (.mq4/.mq5/.ex4/.ex5)** | 专家顾问/自动交易 |
| **指标 (.mq4/.mq5/.ex4/.ex5)** | 自定义技术指标 |
| **脚本 (.mq4/.mq5)** | 一次性执行脚本 |
| **库文件 (.mqh)** | 可复用模块 |

## 三、沉淀标准（Phase 2-3）

### 3.1 筛选标准

| 维度 | 权重 | 说明 |
|------|------|------|
| **代码质量** | 30% | 结构清晰、注释完整、无明显BUG |
| **策略有效性** | 25% | 有明确策略逻辑、可回测验证 |
| **可维护性** | 20% | 模块化程度、接口设计 |
| **许可协议** | 15% | MIT/BSD/Apache优先 |
| **社区活跃度** | 10% | Star数、更新频率 |

### 3.2 沉淀仓库结构

```
source-warehouse/
├── approved/                    # 筛选通过的源码
│   ├── ea/
│   │   ├── signal/            # 信号类EA
│   │   ├── utility/           # 工具类EA
│   │   └── hybrid/            # 混合类EA
│   ├── indicator/             # 技术指标
│   ├── script/               # 脚本
│   └── library/               # 库文件(.mqh)
│
├── pending/                    # 待筛选的源码
│
├──灵感库/                      # 没有源码的灵感来源
│   ├── products/              # 产品灵感
│   └── features/              # 功能灵感
│
└── metadata/
    ├── repositories.json       # 仓库索引
    ├──筛选记录.json           # 筛选决策记录
    └── licenses.json          # 许可协议记录
```

## 四、EA分类（待资源沉淀后确定）

### 4.1 初步分类草案

> ⚠️ **分类待资源沉淀后确定，此为草案**

#### 信号类EA (Signal EAs)
> 基于技术指标生成交易信号的EA

| 分类 | 说明 | 示例策略 |
|------|------|----------|
| 趋势 Trend | 跟随市场方向 | EMA交叉、MACD |
| 网格 Grid | 震荡市场套利 | 网格、马丁格尔 |
| 剥头皮 Scalping | 超短周期 | RSI+MACD |
| 突破 Breakout | 区间突破 | 布林带、Keltner |
| 震荡 Range | 反转策略 | RSI超买超卖 |

#### 工具类EA (Utility EAs)
> 不直接产生交易信号，用于辅助/分析

| 分类 | 说明 | 示例功能 |
|------|------|----------|
| 跟单工具 | 复制交易信号 | 自动跟单 |
| 战绩统计 | 账户分析 | 盈亏/胜率/回撤 |
| 交易日志 | 记录交易历史 | 自动生成报告 |
| 风险管理 | 风控工具 | 头仓计算、止损监控 |
| 通知工具 | 信号推送 | 飞书/TG通知 |

### 4.2 分类确定原则

- ✅ 根据实际沉淀的源码确定最终分类
- ✅ 不预先设定死的分类框架
- ✅ 分类服务于整合和用户体验

## 五、整合策略（Phase 4）

### 5.1 王牌EA策略 (≤3个)

从沉淀的源码中，挑选：

| 标准 | 说明 |
|------|------|
| **性价比** | 功能完整 vs 代码复杂度 |
| **引流效果** | 用户一看就懂、马上能用 |
| **差异化** | 不容易被竞品复制 |

**用途:** 网站核心引流工具

### 5.2 模块化框架策略

| 模块类型 | 来源 | 用途 |
|----------|------|------|
| **可直接复用** | 沉淀代码中抽取 | 整合进自研产品 |
| **参考借鉴** | 代码结构/设计模式 | 赋能自研开发 |
| **接口标准** | 统一抽象层 | 自研与开源模块无缝集成 |

**用途:** 赋能自研产品开发
